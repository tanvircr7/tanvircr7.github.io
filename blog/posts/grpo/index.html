Makes prompt creation/validation easy

Score function: +1 reward for correct, 0 for incorrect

Testing Flow:

GRPO visually explained

Two Major Phases:

Experience Collection → LLM interacts, fills buffer

Training → Update model weights for better rewards

Experience Collection Phase

Step-by-Step:

Sample batch → e.g., 2 questions from environment

Tokenize + Generate → Multiple responses via high temperature sampling

Detokenize → Convert back to string responses

Score → Environment generates reward for each response

✅ Correct + proper format = high rewards

❌ Incorrect/wrong format = low rewards

Advantage Calculation:

Standardize rewards → zero mean, std dev = 1

Group Relative = relative advantage vs other responses to same question

Why called “Group Relative Policy Optimization”

Buffer Storage (4 components per experience):

Full sequence → system prompt + question + LLM answer

Response mask → binary indicator of LLM-generated tokens

Group relative advantage → standardized reward score

Log probabilities → of generated tokens (used in training phase)

Next: Training phase uses these stored experiences to update model weights

Policy Optimization & PPO Loss (Telegraphic)

Core Objective: Maximize Policy Gradient

Equation Breakdown:

First Σ → loops over G responses per question

Second Σ → loops over tokens (t=1 to length) in each response

Result: Nested loop through every token in batch

Key Components

π(θ) × A_it:

A_it = advantage of each token

The easiest way to assign advantage to each token is..

Simple version: Copy response advantage to all tokens

Logic: Every token equally responsible for correct answer

Example: +1 response advantage → +1 for each token

π term (Probability):

Probability of token t in response i

Given: question Q + previous tokens (autoregressive)

Training Logic

Fixed: Advantages (from environment rewards) Variable: Token probabilities (from LLM)

To maximize objective:

↑ Probability of tokens with positive advantage

↓ Probability of tokens with negative advantage

Advanced Components

Importance Sampling (π/π_old):

π_old = policy during experience collection

π = current training policy

Reweights advantages between old/new networks

Clipping Term:

Purpose: Regularization - prevents extreme weight updates

Constraint: Ratio clamped between (1-ε, 1+ε)

Effect: “Don’t change weights too quickly”

Result: Model learns to generate tokens → higher advantages → correct answers
